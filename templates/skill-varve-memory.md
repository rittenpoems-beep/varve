# Varve 记忆检索与写入

安装路径：`<VARVE_HOME>`；数据目录：`<VARVE_DATA>`。

> **L2 是全局卡**（`<VARVE_DATA>\STATUS.md`）：不按项目定义，任何目录共用一张。
> 契约句由 hook 在会话首次用户消息的**尾部**注入一次（与该状态卡同批），此后不再重复。

## 触发判据（出现任一 → 必须先检索、后回答）

- 用户提到**过去**：「上次 / 之前 / 当时 / 那天 / 曾经 / 以前」
- 用户使用**指代**：「那个坑 / 那个方案 / 那件事」
- 用户问**归因**：「为什么这么设计 / 当时怎么想的」（答案在过去）
- 你准备**断言历史事实**：「我们定过 X」「之前用的是 Y」

## 怎么检索

```powershell
python -X utf8 "<VARVE_HOME>\scripts\recall.py" "关键词1" "关键词2" [--since 7d] [--workspace <路径>] [--json]
```

- **多变体一次调用**（程序内部 RRF 合并，比多次单查快且省往返）
- 中文 <3 字词（如「索引」）自动走字面匹配兜底
- 返回含**坐标**（`src: 行号段`）——需要原文时按坐标直接读对应行段
- 查不到 → **直说查不到**，不要补全、不要编
- **演化型问题**（"当时为什么…"）→ 用 `--topic <主题>` 拉主题时间线（三源合并、按时间排开）
- 输出末尾的【覆盖】行 = "命中总量 / 展示量"：**未展示 ≠ 不存在**；证据不全时先声明

## 硬规则 · 断言前置

任何时候要说「我们之前 / 上次 / 曾经…」，**必须先检索**；检索不到就直说检索不到。

## 写入（收尾三问）

1. 这轮有**可迁移原则**（机制/教训）吗？→ 写 `<VARVE_DATA>\records\<项目>.md`（四要素）
2. **环境**变了吗？→ 更新 `<VARVE_DATA>\ENVIRONMENT.md`（动态快照）
3. **任务状态**推进了吗？→ 在**全局卡** `<VARVE_DATA>\STATUS.md` 末尾**追加一条完整快照**（条目用【项目】前缀）

### 怎么写一条快照（快照流，2026-09-25 定稿）

L2 是**只增不减的快照序列**：注入只读**最后一条**，所以上下文占用恒定；旧快照永不修改、永不删除。

1. 读文件末尾那条快照
2. 以它为底，写出**当前完整状态**——**没有变化的项也要照写**（快照必须自洽，这是硬要求）
3. 在文件**末尾**追加：

```text
<!-- ===== 快照 ===== -->

### YYYY-MM-DD HH:MM · 快照

**目标** / **进行中** / **下一步** / **待用户决策** / **本次结束**
```

4. 刚结束的任务写在**新快照的「本次结束」**里（只标注这一次结束的；后续快照不再包含它）；旧快照一个字都不要改

### 写入判据（防膨胀，逐条过闸）

**进 records（不注入，检索才出现）**——三条闸门全过才写：

1. **可迁移**：能写成"以后遇到 X 就做 Y"？（答不出来就不配入库）
2. **会复发**：同类情形还会再遇到？——**一次性失误 / 低概率 / 可即时自愈的，一律不写**（没有第二次受益，写了只是噪音）
3. **未机制化**：还没被脚本 / 规则 / hook 兜住？（已自动化的，备忘无意义）

**进 L2 快照**——门槛更高，只有两类：

- 每次会话都该遵守的**约束 / 偏好**；
- **当前正在推进**的任务状态（目标 / 进行中 / 下一步 / 待决策 / 本次结束）。

> 快照流让**文件**可以无限长，但**单条快照**必须贴住 3500 护栏（`audit.py` 只查最后一条）——
> 所以**快照里只装当前状态，"踩过的坑"和细节一律进 records**。

多写者并发（子 agent / 多会话）时，先写暂存提案再裁决：

```powershell
python -X utf8 "<VARVE_HOME>\scripts\staging\staging_write.py" --writer <你的id> --kind session `
    --target status.task --key "进行中/条目名" --content "改动内容"
python -X utf8 "<VARVE_HOME>\scripts\staging\staging_merge.py" --scan --out plan.json
```
